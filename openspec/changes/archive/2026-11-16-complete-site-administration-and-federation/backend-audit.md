# P4 backend contract audit

Checked against LemmyMultisite commit `87bbe693a`, including tenant-isolation fixes `a7048f9fa` and `5f8d43d80`. Paths below are relative to that repository. The 8536 process runs the workspace debug binary, whose build time is after `87bbe693a`; the API does not expose its exact source revision. The configured `localhost` tenant host returned the current site successfully.

| Area | v4 contract and authorization | Current tenant boundary and follow-up |
| --- | --- | --- |
| Site setup and settings | `POST /site` and `PUT /site` require a site administrator. `CreateSite` and `EditSite` are in `crates/db_views/site/src/api.rs`. | Backend commit `5f8d43d80` scopes rate-limit updates and bulk email-verification and registration-acceptance updates by local site ID. `crates/api/api/src/site/configuration_tenant_tests.rs` contains two-site regression coverage; the archived validation records four passing tests. A reversible current-site name update was also saved and restored against 8536. |
| Site icon and banner | `POST` and `DELETE /site/icon` and `/site/banner` require an administrator; uploads accept an image and return `image_url` and `filename`. | Upload handlers invalidate `SiteView` for the current local site after updating the image. See `crates/routes/src/images/upload.rs` and `crates/db_views/site/src/impls.rs`. |
| Registration applications | `/admin/registration_application/list` is cursor-paged and supports `unread_only`; `PUT /admin/registration_application/approve` takes `id`, `approve`, and optional `deny_reason`. Both require an administrator. | The approval transaction locks an application joined to a local user in the active site and scopes the user update by that site. Backend tenant regression tests are recorded in the archived `fix-tenant-approval-media-purge/validation.md`. |
| Pending follows | `/community/pending_follows/list` accepts `unread_only`, `all_communities`, `page_cursor`, and `limit`; only admins can request all communities. `/community/pending_follows/approve` takes `community_id`, `follower_id`, and `approve`. | The list and action enforce moderator or administrator access. The list does not support a `community_id` filter. See `crates/api/api/src/community/pending_follows/` and `crates/db_views/community_follower_approval/src/api.rs`. |
| Taglines and emoji | `/admin/tagline` and `/custom_emoji` provide create, update, and delete; their list endpoints return cursor pages and a category-filtered collection respectively. Mutations require an administrator. | Both resources carry `local_site_id`, and mutations use site-scoped operations. See `crates/api/api_crud/src/tagline/` and `custom_emoji/`. |
| OAuth provider management | `/oauth_provider` supports administrator create, update, and delete. Provider lists are in `GET /site`; the admin list excludes the secret during serialization. Updates accept an optional secret and do not support changing issuer or client ID. | Provider reads and mutations use site ownership. See `crates/api/api_crud/src/oauth_provider/`, `site/read.rs`, and `crates/db_schema/src/source/oauth_provider.rs`. |
| OAuth sign-in | `/oauth/authenticate` takes code, provider ID, redirect URI, optional PKCE verifier, registration information, and TOTP. The backend checks the provider's site and exact callback URI. | Successful existing-account login sets the normal HttpOnly `jwt` cookie in addition to the response body, allowing the frontend to restore the session with `/account`. Registration and email-verification responses do not create a session. See `crates/api/api_crud/src/user/create.rs` and `crates/api/api/src/site/oauth_tenant_tests.rs`. |
| Instance policy and resolver | `/federated_instances` accepts `kind`, `domain_filter`, and cursor paging. `/admin/instance/allow` and `/block` take a domain and reason; block accepts optional Unix expiry. `/resolve_object` accepts `q`. | Federation policy queries use the tenant ID; resolver applies the current site's private-instance and object visibility rules. See `crates/api/api/src/site/federated_instances.rs`, `admin_allow_instance.rs`, `admin_block_instance.rs`, and `federation/resolve_object.rs`. |
| Users | `/admin/users` lists local users with `banned_only`, `sort`, and cursor paging. `POST /admin/add` takes `person_id` and `added`; the backend enforces the administrator hierarchy. | The list queries `tenant.local_site().id`, and role changes use `read_person_for_site` and `update_for_site`. See `crates/api/api/src/site/admin_list_users.rs` and `local_user/add_admin.rs`. |
| Media | `/image/list` returns a cursor page of `LocalImageView` rows for the administrator's site. `DELETE /image` takes `filename`. | The fixed handler checks the current site and removes that site's media reference; shared aliases remain until their last reference is removed. Backend media tests are recorded in the archived `fix-tenant-approval-media-purge/validation.md`. |
| Permanent purge | `/admin/purge/{person,community,post,comment}` accepts the corresponding target ID and a reason; the handlers require a site administrator and check target ownership. | The fixed person purge scopes side effects to the active site; purge guards reject targets with foreign-site dependencies. Backend purge-guard tests are recorded in the archived `fix-tenant-approval-media-purge/validation.md`. Frontend actions are covered by mocked request, confirmation, failure, and non-admin browser cases; no live purge was performed. |
| Existing reports, modlog, bans, and votes | Reports use `/report/list` and type-specific resolve endpoints; modlog and user bans use `/modlog` and `/admin/ban`. Vote defaults use the site update contract. | Preserve the existing workspaces. Site-update isolation is covered by the backend fix above; use isolated fixtures for destructive moderation acceptance. |

The backend's current `ListCommunityPendingFollows` has no community-specific filter, although the existing community-management view sends `community_id`. The cross-community queue uses only supported fields. The community-specific view requires separate correction to avoid presenting unrelated rows as belonging to a single community.
